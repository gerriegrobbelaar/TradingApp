# 0026 Read-only screens in the web app (K3a)

Status: accepted. Code: `apps/web/src/{lib,components,pages}`.

- **Number and date locale.** Amounts use nl-NL (`€ 1.234,56`, as in Exact and as Dutch accountants read them); dates use en-GB (`12 Nov 2026`) so they sit naturally in English copy and cannot be misread as month/day. Both locales are constants in `lib/format.ts`. Amsterdam is the display zone for instants; `YYYY-MM-DD` calendar dates are never shifted.
- **Money display.** `formatMoney` takes integer minor units (or a `bigint`), builds an exact decimal string with BigInt and hands that string to `Intl.NumberFormat` (v3 keeps every digit; on an engine without string support, detected once, the digits are laid into the locale's pattern from `formatToParts` instead, tested to print identically). A `number` beyond the safe range shows an em dash (it is already wrong). A code Intl rejects is printed in front of the amount, using the currency's exponent from core `currencyScale` (JPY 0, KWD 3). Nothing is divided as a float, so values above 2^53 print exactly when held as `bigint`. A JSON number above 2^53 has already lost precision at `JSON.parse`; the API never sends one (core `money` rejects them). Credits keep the minus sign and add a visually hidden "credit".
- **Never across currencies.** `MoneyByCurrency` stacks one line per currency; no component adds amounts of different currencies. A foreign-currency figure also shows the Exact-stored division-currency amount ("At least" when `dcComplete` is false) and the note "Some items have no amount in EUR yet".
- **List freshness (review K3a).** `OpenItemListResponse.freshness` is the last complete read of that kind (`receivables` for invoices, `payables` for bills; same rule as ADR 0022). Invoices and Payables show the stamp (kept while another filter loads) next to "Balances as of". Empty states are distinct: never read completely ("No invoices read from Exact yet."), read and nothing open ("0 open invoices."), and filters on ("No invoices match these filters."). The Overview says "No data yet." only when the open items were never read; read and empty is "0 open invoices and 0 open bills."
- **Requests.** Every screen read goes through `useResource` / `useCursorList`: the request is aborted when the key (division, filters, sort) changes or the screen unmounts, state of another key is never shown (no flash of the old division), a cursor only goes back with the key it came from, and "Load more" is one request however often it is clicked. Identical concurrent reads are not shared across components (none exist); this is deliberate.
- **Keyboard.** Rows have one real button (Tab, Enter, Space). J and K move focus between row buttons, Enter opens the selection when focus is on the page; the handler is off while typing in an input or while a dialog is open. Escape and the Close button close sheets; focus returns to the opener.
- **Read-only.** No pay, approve, match or reminder control exists on these screens, not even disabled. The Approvals sheet is built from the row itself (K4 has no detail endpoint).
- **Division switch (review K3a).** Open sheets (item, drill-down, approval) are state tagged with their division and are not rendered once the division differs, in the same render as the switch. A relation filter is removed from the address on a switch and no request is sent for it in the new division. A `relationId` that is not a relation of the division gets 404 `unknown_relation` from the list API; the page says so and offers "Show all invoices".
- **Address.** Invalid `view`, `currency`, `relationId` or `sort` values are dropped from the address, never sent. Discrete filter changes push a history entry (Back and Forward restore them); typing in search replaces it. The relation chip shows the name from the rows; `relationName` in the address is only a fallback.
- **Drill-down check.** The sheet compares the server totals of its list (`totalsByCurrency`, all matching rows) with the figure clicked and says so when they differ (data changed since the Overview loaded). A web test computes the Overview with core `buildOverviewKpis` and the list with the API filter rules and checks count and sum of all 12 figures; the worker test checks the same against D1.
- **Rows and contrast.** The design's `--accent-soft` selected row put the chips inside it below 4.5:1, so DataTable rows use `--hover` plus a 3px `--accent-text` bar, and neutral chips in rows use `--ink` (`apps/web/src/contrast.test.ts`; chip and notice pairs on cards and sheets in `packages/ui` `contrast.test.ts`).
- **Relation filter.** The item sheet's "Show all items for this relation" sets `relationId` (and `relationName` for the chip label) in the page URL; filters, status, search and sort live in the URL so a view can be shared and the back button works.
