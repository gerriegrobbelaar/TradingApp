# 0027 Reporting screens, Excel and PDF export (K3b)

Status: accepted. Code: `apps/web/src/pages/{AgeingReport,BalanceSheet,ProfitLoss}.tsx`, `components/{ReportParts,ReportGate,LedgerParts,AccountSheet}.tsx`, `export/`, `lib/{print,report-files}.ts`, `reports.css`, `print.css`.

- **Routes.** `/reporting/{balance-sheet,profit-loss,creditors-ageing,receivables-ageing}` (the menu paths were renamed from the placeholders). Ageing never sends `asOf`: the report is as of today in Amsterdam, read from the response. Balance sheet and P&L send `year` and `period`/`periodTo` only when the user chose them or the address has valid values (invalid ones are also dropped from the address); otherwise the server default applies: the latest period with figures, capped at the current month (12 for another year), reported as `latestPeriodWithData` (review K3b; ADR 0024). The selectors show what the report answered with, offer closing periods 13+ when the year has figures there, and a short line says when a later period has figures. The placeholder-era addresses (`/reporting/profit-and-loss`, `creditors-age`, `receivables-age`) redirect to the new ones with their query.
- **Signs.** Open-item ageing uses K3a's `Money` (negative = credit note, read as "credit"). Ledger figures use plain minus signs: in P&L a negative is a cost, not a credit. nl-NL prints `€ -75,00`.
- **Tables.** Own markup, not `DataTable` (which stacks rows at phone width): a focusable `role=region` scroll area per table, first column pinned only up to 760px. Ageing bars are `role=img` with the percentages in their label; the amounts beside them are the data. Bars use integer basis points for width.
- **Account drill-down.** Report lines carry the Exact account id; the balances endpoint wants ours. The chart (`/api/ledger/accounts`) is read once, on the first click, per administration. The sheet marks the periods the cell is made of (balance sheet 0..P, P&L 1..P), adds them under core's `LEDGER_BALANCE_SEMANTICS` with the cell's sign (liabilities, equity and every P&L line are credit less debit) and checks the sum against the cell; a mismatch (data changed since the report loaded) is said, not hidden.
- **One wording for screen, print and Excel (review K3b).** Column heads ("2026, up to period 10", "Year end 2025 (all periods)", "Variance to budget"), the result label and every check or note come from `lib/report-labels.ts`. In the file the checks sit right under the header block, above the table ("Warning:" for a balance sheet that does not balance, "Note:" for the others), never after hundreds of rows. The ageing file follows the screen's sort and holds every relation; a printed page with a search says so.
- **Mix bars.** Each segment keeps 3:1 against the bar track and the card in both themes (`contrast.test.ts`); a legend under each table names the colours.
- **Percentages.** `formatBps`: integer math, one decimal, half away from zero, em dash for a null base (never 0).
- **Excel.** `fflate` 0.8.3 (MIT, pinned) plus hand-written OOXML in a lazily loaded chunk (`export/download.ts`, dynamic import on click). Money is built from minor units with BigInt text and written into the XML as a true number with a format of the currency's decimals; more than 15 significant digits (Excel keeps 15) becomes exact text instead of a rounded number. Strings are XML-escaped (characters XML 1.0 cannot hold and lone surrogates dropped, cut at 32,000 characters without splitting a pair); text starting `= + - @ tab CR LF`, also behind leading white space or invisible characters and in the full-width forms `＝ ＋ － ＠`, is stored as a string with a leading apostrophe (literal, so a CSV saved from the file stays inert); the exact-digit text of an over-long number gets no apostrophe. Sheet names: 31 characters, no `\ / ? * [ ] :`, not `History`, unique ignoring case. The zip time is clamped to 1980-2099 (a wrong device clock made fflate throw). No formulas are written. One sheet per currency for ageing; frozen header block, widths, landscape fit-to-width. Checked by unzip and parse tests and, when `soffice` exists, by converting to CSV with LibreOffice 24.2 (`export/libreoffice.test.ts`; skipped without it).
- **PDF.** The browser print dialog on `print.css` (user picks Save as PDF); no PDF library. Named page for landscape (ageing, P&L), portrait for the balance sheet; always light and plain whatever the theme; repeated table header, rows not split, totals once at the end, page numbers through `@page` margin boxes (Chrome 131+; elsewhere none). While printing, `<html>` has class `printing` and the title is the file name; both are restored on `afterprint`, on the first input after `print()` returned (headless Chrome never fires afterprint), after 120 s at the latest, and at once if `print()` throws; a second print before that restores the first, so the page title is never lost. Verified with `scripts/k3b-screens.e2e.ts` (Playwright `page.pdf()`; not part of `pnpm test`), which serves `public/_headers` (CSP included): the lazy chunk loads and the `blob:` download works under `script-src 'self'` (CSP does not govern downloads; `_headers` needs no change), axe runs in the real browser with colour contrast, and wide or long reports print without clipping, with titles and totals once.
- **File names.** `camelthorn-<report>-<administration-slug>-<asOf>.xlsx`; balance sheet and P&L use `<year>-p<period>`.
- **Freshness.** One stamp for the ledger balances; chart, comparison year and budgets only speak up when out of date or never read. Never-read ledger shows one empty state.
