# 0027 Reporting screens, Excel and PDF export (K3b)

Status: accepted. Code: `apps/web/src/pages/{AgeingReport,BalanceSheet,ProfitLoss}.tsx`, `components/{ReportParts,ReportGate,LedgerParts,AccountSheet}.tsx`, `export/`, `lib/{print,report-files}.ts`, `reports.css`, `print.css`.

- **Routes.** `/reporting/{balance-sheet,profit-loss,creditors-ageing,receivables-ageing}` (the menu paths were renamed from the placeholders). Ageing never sends `asOf`: the report is as of today in Amsterdam, read from the response. Balance sheet and P&L send `year` and `period`/`periodTo` only when the user chose them or the address has valid values; otherwise the server default (current year, current month) applies. There is no "latest period with data" lookup (no endpoint): open question for K2.
- **Signs.** Open-item ageing uses K3a's `Money` (negative = credit note, read as "credit"). Ledger figures use plain minus signs: in P&L a negative is a cost, not a credit. nl-NL prints `€ -75,00`.
- **Tables.** Own markup, not `DataTable` (which stacks rows at phone width): a focusable `role=region` scroll area per table, first column pinned only up to 760px. Ageing bars are `role=img` with the percentages in their label; the amounts beside them are the data. Bars use integer basis points for width.
- **Account drill-down.** Report lines carry the Exact account id; the balances endpoint wants ours. The chart (`/api/ledger/accounts`) is read once, on the first click, per administration.
- **Percentages.** `formatBps`: integer math, one decimal, half away from zero, em dash for a null base (never 0).
- **Excel.** `fflate` 0.8.3 (MIT, pinned) plus hand-written OOXML in a lazily loaded chunk (`export/download.ts`, dynamic import on click). Money is built from minor units with BigInt text and written into the XML as a true number with a format of the currency's decimals; more than 15 significant digits (Excel keeps 15) becomes exact text instead of a rounded number. Strings are XML-escaped; text starting `= + - @ tab CR` is stored as a string with a leading apostrophe. No formulas are written. One sheet per currency for ageing; frozen header block, widths, landscape fit-to-width. Checked by unzip and parse tests and, when `soffice` exists, by converting to CSV with LibreOffice 24.2 (`export/libreoffice.test.ts`; skipped without it).
- **PDF.** The browser print dialog on `print.css` (user picks Save as PDF); no PDF library. Named page for landscape (ageing, P&L), portrait for the balance sheet; always light and plain whatever the theme; repeated table header, rows not split, totals once at the end, page numbers through `@page` margin boxes (Chrome 131+; elsewhere none). While printing, `<html>` has class `printing` and the title is the file name. Verified with `scripts/k3b-screens.e2e.ts` (Playwright `page.pdf()`; not part of `pnpm test`).
- **File names.** `camelthorn-<report>-<administration-slug>-<asOf>.xlsx`; balance sheet and P&L use `<year>-p<period>`.
- **Freshness.** One stamp for the ledger balances; chart, comparison year and budgets only speak up when out of date or never read. Never-read ledger shows one empty state.
