# 0035 FX decimal arithmetic (Phase 6)

Status: accepted. Code: `packages/core/src/{decimal,fx,ecb}.ts`.

- **No decimal library.** FX here needs only exact scaling, multiplication, one division and comparison. A 100-line BigInt module (`decimal.ts`: parse, multiply, compare, divide with rounding, toString) is auditable in one sitting, adds no supply-chain exposure, no Workers bundle weight and no float. Rejected: decimal.js / big.js (more surface than we use, another dependency to track).
- **Representation.** Money is integer minor units (`bigint`; `number` accepted only when a safe integer, else `unsafe_number`). A rate is a plain decimal string, "units of the currency per 1 EUR" (ECB convention), 12 integer and at most 12 fraction digits, > 0, no sign, exponent or whitespace. `01.50` is normalised to `1.5`; `.5`, `5.`, `1e5`, `+1`, `1,5` are rejected. The ECB publishes 4-6 decimals; 12 is headroom, not precision we claim.
- **Cross rates via EUR.** from -> to = `r_to / r_from`, EUR being 1. The amount is converted as one exact rational: `a * 10^scale_to * r_to / (10^scale_from * r_from)`, with the rates as integers over powers of ten. No intermediate rounding.
- **Rounding rule (the only one).** Round half away from zero, once, at the end, to the target currency's minor unit (`currencyScale`: JPY 0, EUR 2, KWD/BHD 3). So `convert(-a) = -convert(a)`, and 0.005 becomes 0.01. Same currency in and out returns the amount unchanged and needs no rate.
- **Displayed rate.** `rateUsed` and `crossRate` are the from -> to multiplier rounded half away to 12 dp with trailing zeros removed. It is for display and audit only; the amount is never recomputed from it. `formatRateForDisplay` rounds the same way to 6 dp by default.
- **Unrealised difference** = value at today's table minus the base-currency amount booked, in base minor units (positive: we would receive or pay more in the base currency). `impliedBookedRate` is booked / open in major units, 12 dp.
- **Booking (Phase 12)** uses the same functions and the same rule for the month-end revaluation: each open item and balance is converted once from its own amount at the month-end table; differences are summed per ledger account after rounding each item, so the journal equals what the UI shows item by item. Any change of rule needs a new ADR.
- **ECB data.** `parseEcbCsv` accepts SDMX-CSV only, finds columns by header name, skips (and counts) rows with a bad code, date or rate, an empty observation, a denominator other than EUR or a type other than SP00, refuses input over 5 MB and never throws. `buildRateTable` takes the latest observation per currency on or before a date, so a Monday before 16:00 CET uses Friday's rates (`asOf` = Friday) and `ratesDate` keeps each currency's own date. `ecbRequestUrl` can only produce the ECB host and strictly validated dates.
- **Open:** ECB rates are "for information only"; the accountant must still confirm them as the revaluation source (open decision 4).
